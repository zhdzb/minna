## 1. 背景

学习包通常包含 20 至 30 道题。当前批改页一次展示全部结果，不记录用户看到
哪一题，也不能在下次打开时续看。用户时间有限或注意力不足时，需要反复从头定位，
导致批改结果长期积压，并进一步阻塞下一轮学习。

错题流程是另一个独立问题。系统当前会把 `is_correct: false` 的批改项自动写入
错题本，也能把错题标记为 `dismissed`，但缺少手动加入、恢复、批量管理、小批次
训练和训练断点。错题数量增加后，完整列表本身会形成新的学习负担。

本规格将“阅读批改结果”和“练习错题”定义为两个独立工作流。二者可以互相跳转，
但不得共享状态含义。

## 2. 目标

1. 让用户可以用每次 3 至 5 题的节奏消化批改结果，并可靠续接上次位置。
2. 保留完整批改证据，同时降低单次需要阅读的信息量。
3. 支持系统自动收录错题，也支持用户根据主观需要手动加入错题。
4. 支持移出、恢复和批量管理错题。
5. 让错题训练以短会话运行，可暂停、续做并重复练习。
6. 保持批改文件、mastery、复习队列和错题状态的职责边界清晰。

## 3. 非目标

- 不改变 Agent/Codex 生成批改结果的 schema 和评分规则。
- 不在批改结果 JSON 中复制 daily packet 的原题数据；页面继续通过
  `exercise_id` 关联原题。
- 不要求为错题重做再次调用 LLM。重做提交后展示已有批改答案和解释，由用户自评。
- 不因批改结果尚未读完而禁止生成新学习包或继续其他训练。
- 不把“已读”“已看懂”直接解释为题目已掌握。

## 4. 术语与边界

### 4.1 批改结果

一次已提交 daily packet 的结构化 review。它包含正确性、错误标签、参考答案、
可接受变体、解释、重做建议和评分证据。review 文件是不可变的历史学习证据。

### 4.2 批改阅读状态

用户对某份 review 中每个批改项的阅读进度。它只服务于界面续看，不参与评分、
mastery、课程推进或复习调度。

### 4.3 错题

进入错题本、可被重复训练的一道题。来源可以是自动收录的错误批改项，也可以是
用户手动收藏的题目。手动加入不代表原答案错误。

### 4.4 错题训练

从错题本中选取有限题目组成的一次短会话。训练状态、作答记录与是否继续复习，
不得反向修改原始 review。

## 5. 批改结果阅读器

### RR-01 独立状态

系统必须为批改阅读维护独立的持久化状态。推荐文件模式使用
`study/state/review-reading.json`，部署模式通过现有 persistence adapter 保存等价数据。
状态至少包含：

```json
{
  "schema_version": 1,
  "reviews": {
    "review:2026-07-31": {
      "review_file": "study/reviews/2026-07-31-review.json",
      "last_exercise_id": "ex-08",
      "items": {
        "ex-01": { "status": "read", "read_at": "ISO-8601" },
        "ex-08": { "status": "later", "updated_at": "ISO-8601" }
      },
      "updated_at": "ISO-8601"
    }
  }
}
```

允许的阅读状态为 `unread`、`read`、`later`。缺少记录等同于 `unread`。

### RR-02 分段阅读

- 默认每次展示 3 个未读批改项。
- 用户可切换为每次 5 题或查看全部。
- 顶部显示已读数、未读数、稍后处理数和总题数。
- 完成当前批次后，用户可以结束本次阅读，也可以继续下一批。

### RR-03 断点续看

- 每次改变题目阅读状态或移动到下一题时立即保存。
- 再次进入同一 review 时，默认定位到最近位置或第一个未读项。
- 对升级前已经存在的 review，首次打开时允许选择“从第几题继续”；未选择时从
  第一个未读项开始。

### RR-04 每题操作

每个批改项必须提供：

- `已看懂`：标记为 `read`；
- `稍后再看`：标记为 `later`；
- `加入错题`或`移出错题本`：显式管理错题，不改变阅读状态。

### RR-05 信息层级

- 默认显示原题、题目上下文、用户答案、是否正确、参考答案和核心解释。
- 可接受变体、评分维度、置信度等详细证据默认折叠，但必须可查看。
- 原题由 daily packet 与 `exercise_id` 在代码中关联，不写回 review 文件。

### RR-06 筛选与排序

至少支持 `未读`、`稍后再看`、`需要重做`、`全部`筛选。默认以 review 原始题号
排序；筛选不得改变持久化题号或批改证据。

### RR-07 非阻塞

未读批改只显示待处理数量，不得阻塞生成学习包、错题训练、听读训练或课程推进。

## 6. 错题本

### MB-01 自动收录

review 写回后，所有 `is_correct: false` 的题目继续自动进入错题本，并保存题目快照
和对应的 `review_snapshot`。自动同步必须保持幂等，不得为同一 review item 创建重复项。

### MB-02 手动加入

- daily packet 题目和批改结果题目均可手动加入错题本。
- 手动加入必须保存题目快照、来源 daily/exercise 标识和创建时间。
- 若已有 review，则同时保存 review snapshot；若尚无 review，该字段允许为空，后续
  review 写回时合并补齐。
- 正确题可以手动加入；其来源标记为 `manual`，不得改写原始 `is_correct`。
- 同一 daily packet 和 `exercise_id` 只保留一个错题实体，自动与手动来源合并。

### MB-03 状态

错题至少支持以下状态：

- `active`：等待或正在复习；
- `mastered`：用户自评已掌握，保留历史但不进入默认训练池；
- `dismissed`：用户主动移出错题本，可恢复。

“移出错题本”是软删除，不物理删除题目、review snapshot 或尝试历史。

### MB-04 管理能力

- 列表中的操作名称使用`移出错题本`，不使用含义模糊的`删除`。
- 支持单条移出、批量移出、查看已移除项目和恢复。
- 支持按课次、错误标签、到期状态、掌握状态及自动/手动来源筛选。
- 批量操作必须二次确认，并明确显示影响题目数量。

### MB-05 与复习队列的边界

- 错题状态变化不得自动删除历史 review 或修改原始批改。
- `dismissed` 表示不再出现在错题训练池；是否同步取消独立 review queue 项由实现阶段
  显式决定并提示用户，不得静默发生。
- `mastered` 只能作为新的学习证据参与后续调度，不能抹去既有错误证据。

## 7. 错题训练

### MD-01 小批次会话

- 默认每次训练 3 题，可选择 5 题或 10 题。
- 一次只显示一道题，并显示当前进度，例如 `2/3`。
- 题目池可以很大，但当前会话只加载所选数量，不能要求用户一次完成全部 active 错题。

### MD-02 选题

默认优先级为：已到期、近期重复错误、较久未练、其他 active 项。用户筛选后的结果
限制本次选题范围。相同题目不应在同一会话中重复出现。

### MD-03 作答与反馈

- 作答阶段只显示题目，不显示参考答案、解释或原批改答案。
- 提交当前题后展示已保存的参考答案、可接受变体、解释和原错误信息。
- 不额外调用 LLM 批改本次重做答案。
- 提交后用户选择`已经掌握`或`仍需复习`；也可以直接进入下一题，默认视为仍需复习。
- 每次提交都追加 attempt，保留答案和时间，不覆盖历史尝试。

### MD-04 暂停与续做

系统必须持久化当前会话的题目 ID、当前位置和已提交状态。离开页面再返回时可以继续，
也可以明确结束当前会话并在以后创建新会话。

### MD-05 降低积压压力

界面以“本次 3 题”作为主要任务，不以错题总量作为要求完成的任务。总量可以作为次要
信息显示，但不得使用阻塞式提示要求清空错题本。

## 8. 交互分区

导航和页面文案必须区分：

| 区域 | 用户问题 | 主操作 |
| --- | --- | --- |
| 批改结果 | “这次作答哪里需要注意？” | 分段阅读、标记稍后、加入错题 |
| 错题本 | “哪些题值得继续保留？” | 筛选、加入、移出、恢复 |
| 错题训练 | “我现在只练哪几题？” | 创建 3/5/10 题会话、作答、自评 |

不得把“未读批改数”计入“待练错题数”，也不得把“批改已读完”展示为“错题已完成”。

## 9. 数据与兼容性

1. `study/reviews/`、`study/daily/` 和现有错题尝试历史不得被覆盖。
2. 新字段和新状态必须通过 schema validator，并为旧数据提供默认值。
3. 现有 `status: dismissed` 数据继续有效。
4. 旧 review 默认没有阅读记录；其 review 内容和题号保持不变。
5. 本地文件模式与部署 persistence adapter 必须具有等价行为。
6. 所有写操作应记录 Agent Study event；阅读游标的高频保存可采用单独事件或降噪策略，
   但加入、移出、恢复、掌握和会话完成必须可审计。

## 10. 验收标准

- [x] 一份 30 题 review 默认只显示首批 3 个未读项。
- [x] 阅读若干题并刷新页面后，可从保存的位置继续。
- [x] 正确题和错误题都能手动加入错题本，且不改变原批改正确性。
- [x] `is_correct: false` 的题目仍能自动、幂等地进入错题本。
- [x] 错题可以单条或批量移出，并能从已移除列表恢复。
- [x] 错题训练可以选择 3、5 或 10 题，默认 3 题且一次只显示一道。
- [x] 未提交训练答案前看不到参考答案，提交后无需 LLM 即可查看已有反馈。
- [x] 中断错题训练并刷新后，可以继续当前会话。
- [x] 阅读状态变化不更新 mastery、review queue 或原始 review。
- [x] 未读批改不阻塞新的 daily packet 或其他训练。
- [x] 历史 daily、review、log 和 mistake attempt 数据保持完整。
- [x] schema、服务端逻辑和关键 UI 流程具有自动化测试，`npm run verify` 通过。

## 11. 建议实施顺序

1. 批改阅读状态、3 题分段和断点续看。
2. 手动加入、明确的移出操作、恢复及批量管理。
3. 3/5/10 题错题训练会话、训练断点和用户自评。
4. 筛选、选题优先级、事件审计和旧数据迁移完善。

- 错题移除采用可恢复的软删除。
