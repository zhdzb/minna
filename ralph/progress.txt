## Codebase Patterns
- `src/store/mainStore.js` is the current persistence boundary for study state and is the safest place to stage new normalized fields during migration.
- Local mode currently depends on `localStorage`, `/data.json`, and the Vite `/api/save-progress` middleware; keep that compatibility until the persistence adapter is in place.
- Deployed mode must move LLM traffic behind server-side routes and must not depend on browser-stored API keys.
- Existing automated tests use `vitest` with `happy-dom`; new pure data or store logic should get unit tests before UI stories land.
- The current frontend provider flow lives in `src/utils/llmProvider.js`, `config.js`, and `src/components/Settings.vue`; migrate it in stages instead of replacing everything at once.
- Shared server-side LLM helpers should own timeout, retry, provider branching, and secret-safe error shaping in one place so future routes stay thin.
- Store-agnostic server utilities should accept plain data inputs and injectable dependencies like `fetchImpl` to stay easy to test without Pinia or network access.
- Dev middleware routes should stay as thin adapters around reusable `src/server/` modules so Vite-only code does not become the real application layer.
- Exercise-related server routes should reuse `aiPayloadValidators` to keep generation/evaluation validation behavior consistent across frontend and server flows.
- Summary routes should normalize model output into strict JSON contracts before returning responses to UI callers.
- State load/save endpoints should delegate through a server persistence adapter so deployed and local storage behavior can switch without changing route contracts.
- Store save flows should keep in-memory state authoritative and surface persistence failures as user-visible errors instead of reverting state.
- Backup export should stay anchored to `buildPersistableState()` so new normalized fields are automatically included in JSON backups.
- Dashboard mission UIs should display rule-plan metrics directly from `daily_plan` and keep AI enhancement strictly optional.
